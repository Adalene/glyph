Quality checks for the AI icon generator. Each run scores every icon on concept match and visual quality — the two metrics that matter most — plus 5 technical checks.

Each icon in the Glyph library is evaluated against 7 quality metrics. The first 4 are deterministic — instant, free, rule-based checks. The last 3 use an LLM judge (Claude Haiku) to assess visual and semantic quality. Dry Run skips LLM metrics; Live mode runs all 7.

Structural DETERMINISTIC

Validates that the icon data is parseable JSON with a non-empty path string and a tags array of strings. The foundation — everything else depends on this passing.

Pass: path exists + tags is string array
SVG Syntax DETERMINISTIC

Tokenizes the SVG d attribute and checks that only recognized path commands are used (M L H V C S Q T A Z and their lowercase variants), and that the path starts with M or m.

Pass: zero unknown commands
Bounds 2–22 DETERMINISTIC

Checks that all absolute coordinates (uppercase commands: M L H V C S Q T A) stay within [2, 22]. Relative coordinates (lowercase l, h, v, c…) are legitimately negative or large and are skipped.

Pass: zero absolute coordinates outside [2, 22]
Complexity DETERMINISTIC

Counts the total number of path commands. Too few (under 3) suggests a degenerate or empty icon. Too many (over 50) produces an icon that's too dense to be legible at 16px — the typical minimum render size.

Pass: 3 ≤ commands ≤ 50
Semantic LLM JUDGE

A Claude Haiku judge evaluates whether the SVG path represents a recognizable, conceptually appropriate icon for its name. Scores 0–5; icons scoring below 3 fail.

Pass: score ≥ 3 / 5
You are an expert icon design critic evaluating a generated SVG icon path.

ICON CONTEXT:
- Name: "{name}"
- Category: "{category}"
- Style: "{style}"
- SVG path d attribute: "{pathD}"

TASK: Evaluate whether this path represents a recognizable, conceptually
appropriate icon for "{name}". Would a designer recognize this as an
attempt at "{name}"? Do NOT penalize valid geometric representations —
simple concepts can have simple paths.

Respond with ONLY this JSON (no markdown):
{"pass": true|false, "score": 0-5, "reason": "<one sentence>"}

Score: 5=perfect match, 4=good, 3=recognizable, 2=weak,
1=unrelated, 0=wrong/empty. Pass threshold: score ≥ 3.
Design LLM JUDGE

Evaluates visual quality across four sub-dimensions: representation, guideline compliance (stroke-only, geometric, minimal control points), aesthetics (balance, optical centering, legibility at 16px), and overall polish.

Pass: overall score ≥ 3 / 5
You are a senior icon designer reviewing an SVG icon path for visual
quality and design guideline compliance. The icon should match the
style of Lucide, Feather, or Heroicons.

ICON CONTEXT:
- Name: "{name}"
- Category: "{category}"
- Style: "{style}"
- SVG path d attribute: "{pathD}"

EVALUATE on four dimensions:
1. Representation — Does it visually represent "{name}"?
2. Guidelines — Stroke-only, geometric, minimal control points,
   appropriate complexity, coordinates within 24×24 viewBox.
3. Aesthetics — Balanced weight, optically centered, clean. Legible at 16px?
4. Polish — Professional icon or rough draft?

Respond with ONLY this JSON (no markdown):
{"pass": true|false, "score": 0-5,
 "subscores": {"representation": 0-5, "guidelines": 0-5,
               "aesthetics": 0-5, "polish": 0-5},
 "reason": "<one sentence>"}

Score: 5=production-ready, 4=good, 3=acceptable,
2=needs work, 1=poor, 0=unusable. Pass threshold: score ≥ 3.
Tags LLM JUDGE

Evaluates whether the icon's tags are accurate, relevant, and useful for search. Checks that tags include the core concept, useful synonyms, and related terms — and flags any that are misleading or off-topic.

Pass: score ≥ 3 / 5
You are evaluating auto-generated search tags for an SVG icon.

ICON CONTEXT:
- Name: "{name}"
- Category: "{category}"
- Tags: {tags}

TASK: Are these tags accurate, relevant, and useful for searching
for this icon? Do they include the concept, synonyms, or related
terms a user would search for? Are any tags misleading or off-topic?

Respond with ONLY this JSON (no markdown):
{"pass": true|false, "score": 0-5,
 "reason": "<one sentence>", "badTags": []}

Score: 5=excellent utility, 4=good, 3=acceptable,
2=weak/generic, 1=mostly wrong, 0=all wrong.
Pass threshold: score ≥ 3. badTags lists any clearly wrong tags.
